## 2. Выбор настроек bake (обязательный пункт контроллера)

Контроллер велел держать `cell_height ≤ 0.5` и доказать выбор движением врага. Я сначала поставил
`cell_height = 0.1` (смещение 0.2, запас 5×) — и **это оказалось хуже дефолта**. Причины, измерены в
реальном запуске игры, не в теории:

```
WARNING: A navigation mesh that uses a `cell_height` of 0.10000000149012 was assigned to a
navigation map set to a larger `cell_height` of 0.25. This mismatch in cell height can cause
rasterization errors with navigation mesh edges on the navigation map.
WARNING: Property agent_max_climb is floored to cell_height voxel units and loses precision.
```

Первое предупреждение — про **функциональный** риск (ошибки растеризации на краях полигонов), второе —
про потерю точности `agent_max_climb`. Оба исчезают при `cell_height = 0.25`.

**Решение: `cell_height = 0.25`** (дефолт движка). Проверка заморозки выполняется: смещение
`2 * cell_height = 0.5 < path_desired_distance = 1.0`, запас вдвое. Это ровно тот мир, который Task 4
уже измерил эмпирически (заморозка возникала при пороге 0.5 == смещение, то есть при
`2 * cell_height == path_desired_distance`, а не «при любом cell_height 0.25»). На всякий случай
неравенство вынесено в отдельное утверждение, чтобы правка навмеша не смогла вернуть заморозку молча.

> Замечание к формулировке контроллера: «при 0.25 смещение 0.5 — ровно граница тупика». Согласно
> собственному измерению Task 4, тупик был при `path_desired_distance = 0.5`; при принятом в Task 4
> пороге 1.0 смещение 0.5 — это половина порога, а не граница. Граница — `cell_height > 0.25`.
> Фактическое движение врага измерено и подтверждено (360/360 движущихся кадров).

### 2.1 Свойства `NavigationMesh` — ошибка, которую я совершил и починил

Изначально я записал в `.tscn` строки с **слэшем**:

```ini
geometry/collision_mask = 5
geometry/parsed_geometry_type = 0
```

Они **молча игнорировались**. Загрузчик сцены отбрасывает неизвестные свойства без единого
предупреждения. Диагностический `print` в `range_scene.gd` показал реальную картину:

```
[DIAG] prop geometry_parsed_geometry_type = 2 hint=Mesh Instances,Static Colliders,Both
[DIAG] prop geometry_collision_mask = 4294967295 hint=
```

То есть имена свойств — **с подчёркиванием**, а не со слэшем; фактически работал дефолт
`PARSED_GEOMETRY_BOTH` с маской «все слои». Итоговые строки:

```ini
[sub_resource type="NavigationMesh" id="NavigationMesh_range"]
cell_height = 0.25
geometry_collision_mask = 5
geometry_parsed_geometry_type = 1
```

* `geometry_parsed_geometry_type = 1` — `PARSED_GEOMETRY_STATIC_COLLIDERS`. Дефолт 2 («Both») читает
  ещё и меши, а меши лежат на GPU; Godot об этом предупреждает: *«blocks the rendering»*. После
  правки `stderr` запущенной игры **пуст**.
* `geometry_collision_mask = 5` — слои 1 (мир) и 3 (мишени). Мишени обязаны быть в сетке: без них враг
  вёл бы сквозь мишень и упирался бы в неё телом. В сцене есть только геометрия слоёв 1 и 3, так что
  маска не срезает ничего нужного.

Ошибка с именами свойств и предупреждение о слэше записаны комментарием прямо в `range.tscn` —
иначе её повторят.

**Замеры bake в реальной игре:** 33 полигона, **9–11 мс** синхронного bake. Заморозки старта нет.

## 5. НАЙДЕННЫЙ БАГ: враг в тире физически не мог ударить игрока

Это главный результат задачи, и нашла его именно ручная проверка.

**Что было.** `enemy_contact.tscn` задаёт агенту `target_desired_distance = 1.0` (дефолт движка).
Агент останавливается в метре от цели. Контактный урон по спека §6.3 ловится **пересечением двух
хитбоксов** (тела проходят друг сквозь друга): у капсул врага и игрока радиус 0.4 м, значит касание
начинается строго ближе **0.8 м**. В метре зоны не пересекаются.

**Как проявлялось.** Враг доходил до игрока, останавливался в метре и молчал. Никакой ошибки в
консоли, навмеш валиден, все слои на местах, сцена выглядит исправной. Замер в харнессе:

```
=== RESULT: 159 checks, 2 failed ===
      FAILURE: стоп-дистанция врага меньше радиуса контакта двух хитбоксов — контактный урон возможен (got 1.000 м при радиусе контакта 0.800 м = 0.400 + 0.400)
      FAILURE: враг из тира дошёл до игрока и нанёс контактный урон — здоровье игрока упало (за 720 тиков (6.0 с) ни одного тика; HP игрока 100.0 из 100.0)
```

То есть 6 секунд, враг рядом с игроком, **ноль** тиков контакта, HP игрока 100.0 из 100.0.

**Что сделано.** В `range.tscn` у экземпляра врага переопределён `target_desired_distance = 0.5`
(запас 0.3 м до границы касания; `path_desired_distance` не тронут, разморозка пути не затронута).
Причина измерена, а не выведена из спеки, и записана комментарием в самой сцене.

**Чего я НЕ сделал и почему.** Корень проблемы — в `enemy_contact.tscn` (`target_desired_distance = 1.0`),
а этот файл не в моём ведении. Правильное место правки — сцена врага; см. §8.

**Два утверждения, которые это сторожат.** Оба в «Проводке сцены» и оба доказаны красным (§4 C):
арифметическое (`стоп-дистанция < сумма радиусов хитбоксов`) и наблюдательное (здоровье игрока
упало в загруженной сцене). Первое не даёт «починить» стоп-дистанцию, убрав при этом контакт;
второе не даёт оставить арифметику верной, а поведение сломанным.

## F2. Перерешение Task 4 — что именно изменилось

Принятое на ревью Task 4 решение было: `target_desired_distance` и `path_desired_distance` оставить
равными дефолту движка (1.0 и 1.0), потому что 0.5 — пережиток Godot 3 из плана.

**Пересмотрено ровно одно число из двух:**

* `target_desired_distance` 1.0 → **0.5**. Обоснование новое и измеренное: 1.0 м больше радиуса
  контакта двух хитбоксов (0.8 м), то есть это число физически исключает контактный урон.
* `path_desired_distance` **остаётся 1.0** — решение Task 4 в силе полностью. Заморозка врага задаётся
  не им, а смещением навмеша `2 * cell_height`; у тира это 0.5 при пороге 1.0 (запас вдвое),
  и это проверяется отдельным утверждением.

Пин в `tests/enemies.gd` (раздел «Навигация») переписан, а не просто молча переставлен на новое
значение: в нём теперь стоит причина («стоп-дистанция меньше радиуса контакта хитбоксов») и ожидаемое
значение в сообщении об ошибке, чтобы следующий читатель увидел, что 0.5 — это вычисленная величина,

Фолбэк `_NAV_TARGET_DISTANCE` (используется, только если узла агента в сцене нет) обновлён на 0.5
вместе с комментарием: оставить там 1.0 было бы «правдой для мира, которого не существует».
