# Task 8: Ручная перезарядка (R) + старт с 300 очков

**Status:** ready
**Date:** 2026-10-10
**Проект:** VibeFPS (Godot 4.7.2 stable, GDScript, Jolt)

Две правки владельца (ручная проверка), независимые по логике, но в одной задаче.

## Часть A — Убрать автоперезарядку, перезарядка по «R»

Сейчас пистолет сам начинает перезарядку при пустом магазине
(`scripts/pistol.gd`, `_process`, шаг 4: `if _current <= 0 and _reload_remaining
<= 0.0 and _has_valid_data(): start_reload()`; это решение №6 в шапке файла).
Действия `reload` в `project.godot [input]` **нет вообще**.

Требуется:
- **`project.godot`**: добавить действие `reload`, привязанное к **физической**
  клавише R (`physical_keycode = 82`, `keycode = 0`), той же кодировкой, что и
  остальные биндинги (не зависит от раскладки ОС). `deadzone` 0.5.
- **`scripts/pistol.gd`**:
  - Удалить ветку автоперезарядки из `_process`.
  - Добавить обработку действия `reload`: по нажатию (just_pressed) и при
    разрешённом игровом вводе (тот же гейт `InputGate.is_play_input_allowed(
    _mouse_mode_for_play_input())`) вызвать `start_reload()`. Опрос — там же, где
    опрос огня (в `_process`), чтобы гейт ввода был единым; иначе выбрать
    `_unhandled_input` — но гейт обязателен.
  - `start_reload()` не менять (отказ на полном магазине, запрет перезапуска —
    сохранить).
  - Обновить комментарий-решение №6 в шапке файла: теперь перезарядку инициирует
    игрок клавишей R, а не пустой магазин.
- **`tests/weapon.gd`**: переписать `_test_empty_magazine_and_automatic_reload`
  (и его вызов ~строка 378) под новый контракт: **пустой магазин сам НЕ
  перезаряжается**; нажатие действия `reload` запускает перезарядку. Добавить
  проверку гейта (при запрещённом вводе/свободном курсоре R не перезаряжает).
  Остальные проверки перезарядки (блокировка огня, запрет перезапуска, полный
  магазин) — сохранить.
- **`tests/input_actions.gd`**: добавить ассерты: действие `reload` существует,
  у него ≥1 событие и оно — `InputEventKey` с `physical_keycode == 82` (R).

## Часть B — Старт с 300 очков

Владелец: «выдай игроку сразу 300 очков» (чтобы сразу проверить покупку автомата
за 300). Сейчас стартовые очки 0.

- **`scripts/game_state.gd`**: ввести `const STARTING_POINTS := 300` и
  `var points: int = STARTING_POINTS` (комментарий о временном балансе сохранить).
- **Адаптировать тесты, которые предполагали 0** (смысл проверок сохранить, как
  в ruling R10 — меняем пины, а не смысл):
  - `tests/progression.gd:128` «points start at 0» → ожидать `STARTING_POINTS`.
  - Сценарий покупки (`:151-160`) пересчитать под новый старт (там было «300 не
    хватает на 300» — теперь хватает). Сделать значения явными (например,
    выставить `_gs.points` напрямую или начислять вокруг нового старта), чтобы
    арифметика покупки/списания/экипировки по-прежнему проверялась.
  - `tests/interact.gd` (`:310,316,327,379,404`): где сценарий означает «не может
    позволить» — выставить очки явно (например, 0) в подготовке теста; ассерты
    `points == 0` привести в соответствие со смыслом сценария.
  - `tests/enemies.gd:638` «счёт начинается с нуля» → `STARTING_POINTS`;
    `:656` «очков ровно 10» → `STARTING_POINTS + 10`.
  - `tests/save.gd` — проверить, что не задет (он конструирует значения явно).
- Инвариант: автосейв/восстановление роунд-трипят как прежде.
