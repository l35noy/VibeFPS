# VibeFPS — Фаза 0: Фундамент и боевые системы

**Дата:** 2026-10-07
**Статус:** утверждён к реализации
**Область:** подготовить проект к передаче агентам и реализовать Фазы 0–5
**Расположение целевой копии:** `docs/superpowers/specs/2026-10-07-vibefps-foundation-design.md`

---

## 1. Цель

Довести VibeFPS от состояния «работает управление персонажем» до состояния
«игровой цикл лобби → локация → 4 волны → босс → зачистка работает, и каждая
подсистема защищена автопроверкой».

Спецификация описывает архитектуру, значения баланса и правила передачи работы
субагентам. Она не является фактом: по правилу `PROJECT.md` §8 архитектура
фиксируется только после реализации и проверки.

## 2. Текущее состояние (проверено 2026-10-07)

Подтверждено запуском:

- Godot-проект 4.7.2, Jolt Physics, физика 120 Гц, MSAA 4x, 2560x1440 fullscreen.
- `main.tscn`: пол 20x20, `ProceduralSkyMaterial`, `WorldEnvironment`
  с `background_mode = 2` (BG_SKY), `DirectionalLight3D` без теней.
- `player.tscn` / `player.gd`: WASD, обзор мышью, гравитация, прыжок через
  `_unhandled_input`, спринт, kill-plane `y < -50` → respawn на точку старта.
- `tests/headless_smoke.gd`: 31 проверка, 0 failed, 2 warnings.
- `tests/capture.gd` — оконный захват кадров в PNG, `user://captures`.
- `tests/diagnose.gd` — диагностический прогон.

Отсутствует: оружие, стрельба, здоровье, враги, волны, локации, лобби,
очки, сохранение, HUD, звук.

## 3. Найденные дефекты, устраняемые в Фазе 0

| # | Дефект | Почему это важно |
|---|---|---|
| D1 | `_test_fall_off_edge` проходит по неверной причине: телепорт на `y=50`, за 2 с гравитация даёт `y=30.48`, условие `y > -50` зелёное всегда | Проверка не доказывает отсутствие проваливания |
| D2 | В headless мышь не захватывается → 2 warning, тесты обзора пропускаются | Инвариант «обзор только при захваченном курсоре» не защищён |
| D3 | ЛКМ занята переключением захвата мыши | Блокирует реализацию стрельбы |
| D4 | Ввод не гасится при свободном курсоре: игрок бегает и прыгает в меню | Ломает UI и инварианты |
| D5 | Захват привязан к встроенному `ui_cancel`, переназначить нельзя | Нельзя освободить ЛКМ под огонь |
| D6 | Слои и маски коллизий не настроены, все тела 1/1 | Снаряды будут пересекать врагов, враги друг друга |
| D7 | У `DirectionalLight3D` отключены тени | Высота прыжка и границы платформы не читаются |
| D8 | Абсолютный путь к Godot продублирован в `.vscode/settings.json` и чеклисте | Решение: оставить абсолютный путь, сосредоточить в одном файле |

## 4. Фаза 0 — Фундамент

Блокирует все последующие фазы. Строго последовательна.

### 4.1 Единая точка запуска проверок

`tools/run_checks.ps1`:
- содержит единственную константу `$GodotBin = "E:\Godot\Godot_v4.7.2-stable_win64.exe"`;
- принимает необязательный фильтр по имени теста: `.\tools\run_checks.ps1 movement`;
- запускает каждый `tests/*.gd` в режиме `--headless --script`;
- агрегирует коды возврата, печатает таблицу `ИМЯ | КОД | ВРЕМЯ` и
  завершается с ненулевым кодом при любом падении.

### 4.2 Новые actions в `project.godot`

| Action | Клавиша | Назначение |
|---|---|---|
| `fire` | ЛКМ | стрельба |
| `pause` | Esc | освободить/захватить курсор, пауза |
| `interact` | E | выключатель света, двери, точки покупки |

`ui_cancel` больше не используется игровым кодом. Существующие `move_*`,
`jump`, `sprint` не меняются.

### 4.3 Управление вводом

- `_ready()` устанавливает `Input.MOUSE_MODE_CAPTURED`.
- Захват переключается только действием `pause` (Esc). ЛКМ больше не
  переключает захват.
- `InputGate` решает, разрешён ли игровой ввод:
  `Input.mouse_mode == Input.MOUSE_MODE_CAPTURED`.
  Это **чистая функция одного аргумента** — тестируется напрямую, без
  реального захвата мыши, что закрывает D2.
- При свободном курсоре игнорируются: обзор мышью, движение, прыжок,
  спринт, огонь, взаимодействие.
- Получение фокуса окна → курсор захватывается обратно.

### 4.4 Разбивка тестов

| Файл | Что проверяет |
|---|---|
| `tests/smoke.gd` | целостность сцены, загрузка, отсутствие ошибок в консоли (бывший `headless_smoke.gd`) |
| `tests/movement.gd` | ходьба, стрейф, спринт, прыжок, отсутствие остаточного скольжения |
| `tests/input_gate.gd` | чистая функция разрешения ввода, гашение всех каналов |
| `tests/integrity.gd` | отсутствие проваливания через геометрию, корректный respawn |
| `tests/weapon.gd` | стрельба, магазин, перезарядка, скорострельность |
| `tests/projectile.gd` | полёт, попадание, урон, исчезновение |
| `tests/enemies.gd` | здоровье, урон, движение к игроку, смерть |
| `tests/waves.gd` | порядок волн, паузы, зачистка |
| `tests/save.gd` | сохранение, загрузка, повреждённый файл |
| `tests/progression.gd` | очки, покупки, открытие локаций |

Правила:
- `smoke.gd` — регресс-щит, выполняется первым и обязан быть зелёным.
- Проверка, проходящая по неверной причине, считается неисправной
  и подлежит ужесточению.
- `tests/capture.gd` сохраняется и используется для визуальных изменений.

### 4.5 Починка D1

`_test_fall_off_edge` заменяется двумя проверками:
1. **Прямая проверка коллизии**: тело игрока не должно пересекать слой 1
   (мир).
2. **Respawn не на нормальном падении**: игрок, спрыгнувший с края платформы
   на 3 м, не должен респавниться — только падение ниже kill-plane.

### 4.6 Тени

Включить `shadow_enabled = true` у `DirectionalLight3D` в `main.tscn`.

## 5. Команды проверки

```powershell
# все проверки
.\tools\run_checks.ps1

# одна проверка
.\tools\run_checks.ps1 movement

# визуальный захват (оконный режим, нужен рендеринг)
& "E:\Godot\Godot_v4.7.2-stable_win64.exe" --path . --script res://tests/capture.gd
```

Определение готовности задачи: **`run_checks.ps1` завершается с кодом 0**.
Для задач, меняющих материалы, освещение или стиль, дополнительно
прикладываются PNG из `capture.gd`.

## 6. Архитектура

### 6.1 Автозагрузки

| Синглтон | Ответственность |
|---|---|
| `GameState` | очки, открытые локации, купленное оружие и улучшения, здоровье; **владеет переходами между сценами** |
| `SaveSystem` | чтение/запись `user://save.json`, обработка повреждённого файла |
| `Sfx` | единая точка воспроизведения звуковых событий |

Переходы выполняются только через `GameState.enter_location(id)` и
`GameState.return_to_lobby(reason)`. Ни одна игровая сцена не вызывает
`change_scene_to_file` напрямую.

### 6.2 Данные через Resource (.tres)

- `WeaponData` — урон, скорострельность, размер магазина, время перезарядки,
  скорость снаряда, размер снаряда, цвет.
- `EnemyData` — здоровье, урон, скорость, интервал спавна, цвет, тип.

Балансировка правится в инспекторе без изменения кода. Отдельные `.tres`
позволяют разным агентам работать над разными данными без конфликтов.

### 6.3 Слои коллизий

| Слой | Содержимое | Тип |
|---|---|---|
| 1 | Мир (геометрия локации, пол, стены) | StaticBody3D |
| 2 | Тело игрока | CharacterBody3D |
| 3 | Тело врага | CharacterBody3D |
| 4 | Хитбокс врага | Area3D |
| 5 | Снаряд | Area3D |
| 6 | Интерактивные объекты (выключатель, двери, точки покупки) | Area3D |
| 7 | Хитбокс игрока | Area3D |

Маски:
- Игрок: тело на слое 2, маска `1 | 7`.
- Враг: тело на слое 3, маска `1 | 3` (не пересекает игрока, чтобы не
  блокировать его движение; контактный урон через слой 7).
- Снаряд: слой 5, маска `1 | 4`. Детектит геометрию через `body_entered`,
  хитбоксы врагов через `area_entered`. Тела врагов (слой 3) в маску не
  входят — двойного счёта нет.
- Хитбокс врага: слой 4, маска `7` — ловит хитбокс игрока для контактного
  урона.

### 6.4 Структура сцен

```
lobby.tscn + lobby.gd             — лобби, магазин, двери
location_01.tscn + location_01.gd — первая локация
player.tscn + player.gd
data/weapons/pistol.tres          — данные оружия
data/enemies/*.tres               — данные врагов
scripts/                          — переиспользуемые скрипты
tests/                            — автопроверки
tools/run_checks.ps1              — единая точка запуска
```

Каждая локация — собственная сцена и собственный скрипт с общим контрактом
`start()` / `clear()`. Добавление локации = добавление файла, без изменения
существующих.

## 7. Базовые значения (утверждены)

### 7.1 Пистолет (стартовое оружие)

| Параметр | Значение |
|---|---|
| Урон снаряда | 30 |
| Скорострельность | 120 выстр./мин (2 выстр./с) |
| Размер магазина | 10 |
| Время перезарядки | 1.2 с |
| Скорость снаряда | 40 м/с |
| Боезапас | бесконечный |
| Визуал | геометрический снаряд со слабым исчезающим шлейфом |

Расчёт: магазин опустошается за 5 с, перезарядка занимает 19% цикла.
На дистанции 15 м снаряд летит 0.375 с — уклонение врага и игрока реально.

### 7.2 Игрок

- Здоровье: 100.
- Контактный урон врага: 10 → 10 попаданий до смерти.
- Восстановление: только в лобби.

### 7.3 Враги

| Враг | Здоровье | Урон | Поведение |
|---|---|---|---|
| Контактный | 50 | 10 | приближается через NavigationAgent3D, урон при контакте |
| Летающий | 40 | — | зависает на дистанции, стреляет геометрическими снарядами |
| Босс | 600 | — | одна фаза, одна телеграфированная атака по площади, слабое место ×2 |

### 7.4 Первая локация

| Волна | Состав | Суммарное HP |
|---|---|---|
| 1 | 10 контактных | 500 |
| 2 | 20 контактных | 1000 |
| 3 | 15 контактных + 5 летающих | 950 |
| 4 | босс | 600 |

Итого 2300 HP ≈ 96 попаданий ≈ 80 с чистой стрельбы.

Спавн: от 12 м от игрока и дальше, в пределах локации, точка не внутри геометрии.
Интервал появления: 1–2 с. Отсчёт перед первой волной: 10 с.
Пауза между обычными волнами: 10 с.

### 7.5 Очки

| Событие | Очки |
|---|---|
| Уничтожение врага | 10 |
| Завершение волны | 50 |
| Зачистка локации | 500 |

Полный проход первой локации: 500 + 200 + 500 = **1200 очков**.

## 8. Изменения правил относительно PROJECT.md

Три решения расходятся с текущим текстом. Спека фиксирует их явно;
в `PROJECT.md` они попадут **после реализации и проверки**, согласно §8.

1. **§9.9** — «каждый враг имеет одну хитбокс-зону».
   У босса появляется второе хитбокс-пространство — слабое место с
   множителем урона ×2. Реализуется полем `damage_multiplier` на
   `EnemyHurtbox` (обычные враги: `1.0`). Для обычных врагов правило
   не меняется.
2. **§9.4** — «примерно один враг каждые 1–2 секунды».
   Сохраняется, добавляется ограничение: не ближе 12 м от игрока.
3. **§9.2** — «длительность первого отсчёта пока не определена».
   Определена: 10 секунд.

Закрываются открытые решения чеклиста: состав волн, характеристики
пистолета, здоровье игрока и врагов, поведение летающего, структура босса.

## 9. Порядок фаз и параллелизм

Работа передаётся субагентам подходом «фазы с параллелизмом». Внутри фазы
задачи независимы только если не делят файлы; карта владения файлами
указана в плане.

| Фаза | Содержимое | Параллелизм |
|---|---|---|
| **0** | Фундамент: `run_checks.ps1`, actions, гашение ввода, `InputGate`, разбивка тестов, починка D1/D2, тени | нет — строго последовательно |
| **1** | Оружие, снаряды, `WeaponData` | нет |
| **2** | Здоровье, урон, контактный враг, навигация, слои коллизий | нет |
| **3** | Летающий враг, босс, спавн, волны, сцена локации | да: враги ∥ сцена локации |
| **4** | Лобби, очки, покупки, сохранение, двери | да: лобби ∥ сохранение |
| **5** | HUD, экраны смерти и зачистки | да |
| **6** | Вторая локация, баланс, звук, производительность | нет |

## 10. Правила передачи задач субагентам

Каждая задача формулируется самодостаточным промптом и содержит:

1. **Цель** — что должно работать после выполнения, в терминах игрока.
2. **Файлы во владении** — точный список. Запрещено трогать файлы вне списка.
3. **Запреты** — что агент не должен менять без отдельного решения.
4. **Команда проверки** — `.\tools\run_checks.ps1 <имя>`.
5. **Критерий готовности** — код возврата 0.
6. **Ограничение области** — несвязанные улучшения запрещены.

Агенты не наследуют контекст Lead. Отчёт агента не является доказательством:
результат определяется кодом и выводом `run_checks.ps1`.

## 11. Критерии приёмки по фазам

**Фаза 0:**
- `run_checks.ps1` запускает все тесты и возвращает 0.
- Проверка отсутствия проваливания проходит по существу, а не по
  неверной причине.
- Тест разрешения ввода проходит без реального захвата мыши.
- В headless нет warning'ов.
- При свободном курсоре движение, прыжок и огонь не срабатывают.

**Фаза 1:** пистолет стреляет, магазин и перезарядка работают, снаряд
наносит урон и исчезает.

**Фаза 2:** враг получает урон, приближается через навигацию, наносит
контактный урон, умирает и теряет цвет.

**Фаза 3:** локация проходится целиком — тёмный старт, выключатель,
отсчёт, 4 волны, босс, зачистка.

**Фаза 4:** лобби даёт полное здоровье, покупки и очки сохраняются,
прогресс переживает перезапуск.

**Фаза 5:** HUD показывает счёт, здоровье, магазин и перезарядку.

## 12. Риски

| Риск | Что делаем |
|---|---|
| 20 контактных врагов на волне 2 могут просадить FPS | Замер FPS при максимуме врагов — обязательная проверка в Фазе 6, не опциональная |
| 40 м/с снаряд при 20 врагах — игрок может не успевать уворачиваться | Балансировка в Фазе 6; состав волн согласован, менять только по факту |
| Запечённая навмеш-карта требует перестройки при изменении геометрии | Агент, меняющий геометрию локации, обязан перестроить навмеш в той же задаче |
| Разбивка тестов на 10 файлов — агенты могут переименовать их | Карта владения файлами фиксируется до начала параллельной фазы |
