# VibeFPS — Фаза 1: Оружие и снаряды — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Дать игроку пистолет, который стреляет видимыми снарядами с конечной скоростью, с магазином, перезарядкой и бесконечным боезапасом — и дать проверке, чему всему этому научиться.

**Architecture:** Данные оружия живут в Godot Resource (`.tres`), поведение — в трёх скриптах: снаряд, пистолет, хитбокс. Никаких иерархий наследования «под будущее»: одно оружие — один скрипт, параметризованный ресурсом. Всё, что можно проверить headless, проверяется headless.

**Tech Stack:** Godot 4.7.2 stable (`E:\Godot\Godot_v4.7.2-stable_win64.exe`), GDScript, Jolt Physics, Jolt `Area3D`, PowerShell.

**Spec:** `~/.opencode/plan/2026-10-07-vibefps-foundation-design.md` — разделы 6.2 (WeaponData), 6.3 (слои коллизий), 7.1 (ТТХ пистолета), 7.4 (волны), 9.8 (оружие).

**Предыдущая фаза:** Фаза 0 закрыта. 5 проверок зелёные, 88 утверждений, каждая проверка доказана способной падать.

## Review Focus

Что спека подразумевает, но ни одна задача не покрывает:

1. **Пустой магазин и нажатие `fire` в один кадр.** Перезарядка начинается, и в тот же кадр игрок жмёт огонь. Ожидание: выстрел не происходит, и перезарядка не сбрасывается. → `tests/weapon.gd`.
2. **Перезарядка при переходе в лобби и обратно.** Магазин остаётся полупустым, игрок получает бесплатные выстрелы каждый раз. Ожидание: при смене сцены оружие сбрасывается в полный магазин. → Фаза 3 (лобби), здесь зафиксировать контракт.
3. **Снаряд, пересекающий хитбокс на скорости 40 м/с между кадрами.** Один кадр = 0.33 м при 120 Гц. Ожидание: попадание регистрируется. → `tests/projectile.gd`.
4. **Хитбокс уже 1/3 м.** Обнаружение `Area3D` дискретное: за один тик снаряд пролетает ровно треть метра, поэтому хитбокс тоньше этого пролетается между отсчётами, и никакая правка снаряда это не лечит — нужен `ShapeCast3D`, который бриф запрещает. Ожидание: любой хитбокс в проекте не тоньше 0.5 м. → частично закрыто в `tests/projectile.gd`, **полностью — это задача Фазы 2, где появляется первый настоящий враг.**
4. **Снаряд, выпущенный в тот же кадр, когда сцена выгружается.** Узел может быть освобождён между выстрелом и обработкой попадания. Ожидание: без ошибок в консоли. → `tests/projectile.gd`.
5. **Два снаряда в один хитбокс в одном кадре.** Ожидание: урон применяется один раз. → `tests/projectile.gd`.

Ни одна из этих линий не закрывается полностью в Фазе 1; 1, 3, 4, 5 закрываются здесь.

### Task 2: Снаряд и хитбокс

**Files:**
- Create: `scripts/hurtbox.gd`
- Create: `scripts/projectile.gd`
- Create: `tests/projectile.gd`

**Interfaces:**
- Produces: `class_name Hurtbox extends Area3D` с полем `@export var damage_multiplier: float = 1.0` и методом
  `func apply_damage(amount: float) -> void`, который вызывает сигнал `damage_taken(amount: float)` и ничего не делает с собственным состоянием — состояние здоровья у владельца, не у хитбокса. Сигнал: `signal damage_taken(amount: float)`.
  Слой 4 (`enemy_hurtbox`), маска `1` — хитбокс не должен ловить игрока.
  Поле `damage_multiplier` — то самое, через которое в Фазе 2 будет сделано слабое место босса с ×2. Обычные враги: `1.0`.

- Produces: `class_name Projectile extends Area3D`:
  - сигнал `signal hit_something(target: Node)` — выстрел попал во что-то (для диагностики и тестов)
  - `@export var speed: float = 40.0`
  - `@export var damage: float = 30.0`
  - `@export var lifetime: float = 3.0`
  - `func launch(direction: Vector3) -> void` — задаёт направление, **не** двигая узел, и включает обработку
  - внутреннее: движение строго в направлении `direction`, нормализованном один раз при запуске; никакого гравитационного ускорения и никакого отскока (прямолинейность — решение спеки)
  - попадание определяется через сигналы Area3D: `area_entered` для хитбоксов (слой 4) и `body_entered` для геометрии мира (слой 1)
  - **слой 5** (`projectile`), маска `1 | 4`
  - **немедленно исчезает при первом попадании** — иначе один снаряд нанесёт урон нескольким целям за кадр
  - `queue_free()` по истечении `lifetime`
  - слабый исчезающий шлейф: дочерний `MeshInstance3D`, у которого прозрачность падает по времени жизни. Реализация шлейфа — через материал с `TRANSPARENCY_ALPHA` и `albedo_color.a`, уменьшаемым каждый кадр; **не** через `Tween`, потому что `Tween` продолжает работать после попадания, а шлейф должен умирать вместе со снарядом.

### Task 3: Пистолет — магазин, перезарядка, огонь

**Files:**
- Create: `scripts/pistol.gd`
- Create: `tests/weapon.gd`

**Interfaces:**
- Consumes: `WeaponData` из Task 1, `Projectile` и `Hurtbox` из Task 2, `InputGate` из Фазы 0, действие `fire` из `project.godot`.
- Produces: `class_name Pistol extends Node3D`:
  - `@export var data: WeaponData` — характеристики
  - `@export var projectile_scene: PackedScene` — сцена снаряда для инстанцирования
  - `@export var fire_rate_source: Node3D` — откуда выпускать снаряд; по умолчанию сама камера игрока
  - `signal fired()` — выстрел произошёл
  - `signal reload_started()` / `signal reload_finished()`
  - `signal magazine_changed(current: int, capacity: int)`
  - `func can_fire() -> bool` — данные валидны, курсор захвачен, не перезаряжается, магазин не пуст
  - `func try_fire() -> bool` — выпускает снаряд, уменьшает магазин, возвращает `true` если выстрел был
  - `func start_reload() -> bool`
  - `func current_mag() -> int`
  - `func is_reloading() -> bool`
  - `func reset_for_scene_change() -> void` — **контракт на будущее**: полный магазин, без перезарядки, обнуление таймера. Существует сразу, чтобы Фаза 3 (лобби) не оставила игроку бесплатные выстрелы. Вызывается из `player.gd::_ready()`.

- [ ] **Step 1: Написать падающую проверку `tests/weapon.gd`**

Пистолет тестируется **без сцены и без игрока**: он создаётся программно, источник выстрела — фиктивный узел, `InputGate` подменяется швом так же, как в `movement.gd`. Это изолирует логику оружия от ввода и геометрии.

Утверждения:
- **стартовый магазин полон:** `current_mag() == 10`
- **выстрел уменьшает магазин:** после `try_fire()` магазин 9, сигнал `fired` пришёл ровно один раз
- **пустой магазин блокирует огонь:** после 10 выстрелов `try_fire()` возвращает `false`, магазин остаётся 0, 11-й `fired` не приходит
- **перезарядка заполняет магазин:** после пустого магазина `start_reload()` возвращает `true`, через `1.2 * 120 = 144` кадра физики магазин снова 10
- **перезарядка не выдаёт выстрелов:** `try_fire()` во время перезарядки возвращает `false`
- **перезапуск перезарядки запрещён:** `start_reload()` во время перезарядки возвращает `false` и **не** сбрасывает таймер — иначе игрок бесконечно продлевает перезарядку, откладывая её
- **темп стрельбы соблюдается:** два выстрела подряд без ожидания дают ровно один выстрел, второй — после интервала `0.5 * 120 = 60` кадров
- **ввод гейтится:** при режиме мыши, отличном от `CAPTURED`, `try_fire()` возвращает `false` — действие `fire` не обходит гейт ввода
- **контракт смены сцены:** `reset_for_scene_change()` даёт полный магазин и снимает перезарядку
- **невалидные данные блокируют огонь:** при `magazine_size = 0` `can_fire()` возвращает `false` — защита от ресурса с нулевым магазином, а не деление на ноль

- [ ] **Step 3: Создать `scripts/pistol.gd`**

Состояние: `_current`, `_reload_remaining: float`, `_cooldown: float`.

Порядок обновления в `_process(delta)`:
1. `_cooldown = maxf(0.0, _cooldown - delta)`
2. если `_reload_remaining > 0.0`: уменьшить; при достижении нуля заполнить магазин, испустить `reload_finished`, испустить `magazine_changed`
3. если `Input.is_action_pressed("fire")` — вызвать `try_fire()`

`_process`, а не `_physics_process`: стрельба — игровое действие с частотой кадров рендера, а не физическая симуляция. Темп при этом считается в секундах через `data.seconds_between_shots()`.

Внутри `try_fire()` порядок обязателен: сначала проверки `can_fire()`, затем инстанцирование снаряда, затем `_current -= 1`, затем `_cooldown = data.seconds_between_shots()`, затем сигналы. Если уменьшать магазин до инстанцирования, то провалившийся инстанцирование съест патрон.
