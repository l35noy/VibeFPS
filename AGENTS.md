# AGENTS.md — структура документации VibeFPS

Этот файл описывает структуру документации VibeFPS — что где лежит. Канон — только `docs/`.

## Назначение папок и файлов

| Путь | Назначение |
|---|---|
| `docs/PROJECT.md` | Постоянный контекст проекта: архитектура, принятые решения, механики. Канон описания «как устроена игра». |
| `docs/CHECKLIST.md` | Состояние прохождения: что сделано, что открыто, инварианты, открытые решения. Канон статуса работ. |
| `docs/done/` | «Пройдено» — завершённые фазы. По одной папке на фазу (`phase0-foundation`, `phase1-weapons`, `phase2-enemies`, `phase3-lobby`). |
| `docs/done/<phase>/design.md` | Спека/дизайн завершённой фазы (если была). |
| `docs/done/<phase>/plan.md` | План завершённой фазы. |
| `docs/done/<phase>/handoff.md` | Передача контекста между фазами (если была). |
| `docs/done/<phase>/reports/` | Протоколы работ фазы: `brief` (задача) и `report` (отчёт). |
| `docs/done/patches/` | Мини-работы вне фаз (`shoot-fix`, `balance`, `doc-cleanup`, `phase-reorder`). Их протоколы лежат прямо в папке патча. |
| `docs/todo/` | «Предстоит» — будущие фазы и навигация по ним. |
| `docs/todo/ROADMAP.md` | Краткая навигация по будущим фазам (4–7) на основе открытых разделов `docs/CHECKLIST.md`. |
| `AGENTS.md` (корень репозитория) | Этот файл — истина о структуре документации. Единственный файл структуры вне `docs/`. |

## Правила

1. **Канон — только в `docs/`.** Всё вне `docs/` (кроме корневого `AGENTS.md`) устарело; корневые копии документов не хранятся.
2. **Дублей нет.** Один факт — в одном месте. Копии одного документа в дереве недопустимы.
3. **Имена:** английские, короткие, без дат (дата и так видна в git). Примеры: `plan.md`, `handoff.md`, `task-1-report.md`.
4. **Шапка назначения.** Каждый `.md` в `docs/` начинается с 1–3 строк: что это за документ и зачем он.
5. **Жизненный цикл фазы.** Новая фаза сначала живёт в `docs/todo/<phase>/`; после завершения переносится в `docs/done/<phase>/`.
6. **Протоколы.** `brief` + `report` — читаемые протоколы в `<phase>/reports/`. Полные diff-пакеты и review-пакеты в дереве **не хранятся** — diff живёт в git.
7. **Куда класть и как называть новое:**
   - новый план/спека фазы → `docs/todo/<phase>/plan.md` (позже переедет в `done/`);
   - отчёт по задаче → `docs/done/<phase>/reports/task-N-report.md` (или `<patch>/...` для патчей);
   - разовая мини-работа → `docs/done/patches/<name>/`.
8. **Канон-ссылки.** Постоянный контекст — `docs/PROJECT.md`; статус — `docs/CHECKLIST.md`; будущее — `docs/todo/ROADMAP.md`. Ссылки между ними должны разрешаться.
